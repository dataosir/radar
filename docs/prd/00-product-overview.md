# 00 · 产品概览

## 1. 产品定位

**TG-RADAR** 是面向**个人求职者**的 Telegram 招聘信息雷达，不是招聘平台、不是 HR 工具、不是群发 Bot。

引擎默认回答是「不相关」。只有当消息命中**过滤规则**（未来可加 LLM 评分），才进入每日 digest。

> 一句话：不帮你找工作，只回答——**今天哪些新帖值得我花 30 秒点开？**

## 2. 目标用户与场景

| 角色 | 场景 |
|---|---|
| **我（founder / 求职者）** | 订阅了 10–30 个 Telegram 招聘频道，每天信息过载 |
| 未来：同类求职者 | 若自用 2 周有效，可包装为 Idea 8-D2 垂直产品 |

## 3. 核心价值主张

1. **增量拉取**：只处理上次游标之后的新消息，不重复扫历史。  
2. **可配置过滤**：Java / Spring / 远程 / GraalVM 等正向词；外包刷量等排除词。  
3. **可审计**：每条入选帖带来源链接、命中规则、原始摘要。  
4. **低维护**：单机 CLI + launchd；无数据库。

## 4. 非目标（明确不做）

| 不做 | 原因 |
|---|---|
| 代投简历 / 自动私信 HR | 产品边界；合规风险 |
| 爬取未订阅频道 | ToS / 隐私 |
| 多租户 SaaS（现阶段） | 先验证自用价值 |
| 微信/QQ 适配 | 见 indie-build-log Idea 8 主 wedge |
| 保证拿到 offer | 工具只整理信息，非结果承诺 |

## 5. 成功度量（自用阶段）

| 指标 | 说明 | 目标 |
|---|---|---|
| 日扫描耗时 | `digest` 命令端到端 | < 2 分钟 |
| 噪音率 | digest 里「点开即关」占比 | < 30% |
| 漏帖率 | 事后发现相关帖未进 digest | < 5% |
| 连续使用 | 是否每天主动跑 | ≥ 14 天 |

## 6. 系统边界图

```
Telegram 频道(F01) → 规则过滤(F02) + 去重(F03)
                ↓
           Digest 报告(F04) → reports/
                ↓
           可选提醒(F05)
配置 · selftest 横切全链路
```
